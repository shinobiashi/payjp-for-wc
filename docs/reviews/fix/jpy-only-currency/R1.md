## 指摘
### [R1-1][Medium][tests/Unit/CurrencyCheckTest.php:180]
注文が見つからない場合のテストが USD ストアの `assertFalse` だけで、「ストア通貨へのフォールバック」と「不明として拒否」を区別できない。`get_checkout_currency()` が空文字を返す実装に変えても全テストが通る(サブエージェントが変異で確認)。JPY ストアで `?order-pay=<存在しない ID>` のときゲートウェイが消える回帰を検知できない。
**修正方針:** JPY ストアで `assertTrue` も確認する。

### [R1-2][Medium][includes/gateways/payjp/class-wc-gateway-payjp.php:172, docs/architecture.md:105, tests/Unit/CurrencyCheckTest.php:191]
`process_payment()` のガードが必要な理由を「古いチェックアウト画面」と説明していたが誤り。古い画面からの POST でも `is_available()` は再評価される(`class-wc-checkout.php:1063`、`StoreApi/Routes/V1/Checkout.php:986`)。実際に届くのは `order-pay` のクエリ変数が無い Store API `CheckoutOrder` と、`?order-pay=` を付けた新規チェックアウト。コメント相当だが、設計ドキュメントの事実誤りなので Medium に上げた。
**修正方針:** コメント・`docs/architecture.md`・テストの説明を実際の経路に合わせる。
